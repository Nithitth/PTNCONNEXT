# แผนรับมือเหตุข้อมูลรั่ว / ถูกเจาะระบบ

ใช้เมื่อสงสัยว่ามีคนเข้าบัญชีที่ไม่ใช่ของตัวเอง ข้อมูลหลุด กุญแจลับรั่ว (เช่น เผลอส่ง `.env.local` ให้คนอื่น) หรือเห็นสิ่งผิดปกติในคอนโซล
**กฎหมาย PDPA: ต้องแจ้ง สคส. ภายใน 72 ชั่วโมงหลังรู้เหตุ** (ถ้าเหตุมีความเสี่ยงต่อสิทธิของเจ้าของข้อมูล) จดเวลาที่รู้เหตุไว้ตั้งแต่ข้อแรก

## 1. สังเกตเหตุ (ทุกวัน 2 นาที)

คอนโซลผู้พัฒนา → **ลงทะเบียน & เข้าสู่ระบบ**
- ภาพรวม: “ถูกล็อกเพราะใส่รหัสผ่านผิดหลายครั้ง”, รหัสห้อง/รหัสครูผิด, ชื่อที่ลงทะเบียนแล้วถูกใช้ซ้ำ
- ประวัติ: “ล็อกอยู่ตอนนี้”, “การกระทำของผู้ดูแล” (มีการรีเซ็ตรหัสผ่านหรือปิดสองขั้นตอนที่ไม่มีใครทำหรือไม่)
- นักเรียนหรือครูแจ้งว่า “มีคนลงทะเบียนชื่อฉันแล้ว” หรือ “ฉันไม่ได้เข้าสู่ระบบ แต่มีอีเมลรหัสยืนยันมา”

## 2. หยุดความเสียหาย (ภายใน 1 ชั่วโมง)

ทำเท่าที่เกี่ยวข้อง:
- [ ] **ปิดรับลงทะเบียน:** ภาพรวม → สวิตช์ “ปิดรับลงทะเบียน”
- [ ] **บัญชีเดียวถูกเข้า:** ผู้ใช้ → รีเซ็ตรหัสผ่าน (และ “ปิดการยืนยันสองขั้นตอน” ถ้าโทรศัพท์หาย) หรือ ห้องเรียน → “ยกเลิกการลงทะเบียน” ถ้าเป็นคนอื่นลงทะเบียนแทน
- [ ] **ให้ทุกคนออกจากระบบทันที:** Supabase → Project Settings → **JWT Keys** → สร้างกุญแจใหม่ (rotate) ทุกคนต้องเข้าสู่ระบบใหม่
- [ ] **กุญแจลับรั่ว:** สร้างใหม่แล้วใส่ใน Vercel → Environment Variables → Redeploy
  - `SUPABASE_SERVICE_ROLE_KEY` (Supabase → API Keys → สร้าง secret key ใหม่ แล้วลบอันเก่า) — **สำคัญที่สุด**
  - `LOGIN_EMAIL_SECRET` → จากนั้นรัน `npm run migrate:auth-emails -- --env=.env.production.local --apply` ทันที ไม่อย่างนั้นไม่มีใครเข้าสู่ระบบได้
  - `SIGNUP_SECRET` (รหัสส่วนตัวที่ยังไม่ได้ใช้จะใช้ไม่ได้ ต้องสร้างให้ใหม่), `CRON_SECRET`
  - รหัสผ่านแอปของ Gmail (`SMTP_PASS`): Google Account → Security → App passwords → ลบอันเก่า สร้างใหม่
  - Google Drive: `GOOGLE_CLIENT_SECRET` (Google Cloud → Credentials → สร้าง secret ใหม่ ลบอันเก่า) และ `GOOGLE_TOKEN_SECRET` ถ้าเปลี่ยน `GOOGLE_TOKEN_SECRET` ครูทุกคนต้องกด “เชื่อมต่อ Google Drive” ใหม่ (ไฟล์เดิมใน Drive ยังอยู่)
- [ ] **บัญชีของทีม** (Supabase, Vercel, GitHub, Gmail): เปลี่ยนรหัสผ่าน ตรวจว่าเปิดสองขั้นตอนอยู่

## 3. ประเมิน (ภายใน 24 ชั่วโมง)

- ใคร / ข้อมูลอะไร / ช่วงเวลาไหน: ดู “ประวัติ” ในคอนโซล, Supabase → **Logs** (Auth และ API), Vercel → **Logs**
- จดเป็นข้อความสั้น ๆ: เกิดอะไร รู้เมื่อไร ข้อมูลประเภทไหน กี่คน ทำอะไรไปแล้ว

## 4. แจ้ง (ภายใน 72 ชั่วโมงหลังรู้เหตุ)

- [ ] ผู้อำนวยการโรงเรียน (ผู้ควบคุมข้อมูล) — ทันที
- [ ] **สคส.** (สำนักงานคณะกรรมการคุ้มครองข้อมูลส่วนบุคคล) ผ่านช่องทางแจ้งเหตุบนเว็บไซต์ของ สคส. ถ้าเหตุมีความเสี่ยงต่อสิทธิของนักเรียนหรือครู
- [ ] ผู้ได้รับผลกระทบ (นักเรียน ผู้ปกครอง ครู) ถ้าความเสี่ยงสูง: บอกว่าเกิดอะไร ทำอะไรไปแล้ว และควรทำอะไร (เช่น เปลี่ยนรหัสผ่าน)

## 5. หลังเหตุ

- [ ] แก้สาเหตุ แล้วรัน `npm run check:security` บนฐานข้อมูลทดสอบ
- [ ] เปิดรับลงทะเบียนอีกครั้งเมื่อแน่ใจ
- [ ] เก็บบันทึกเหตุ (ข้อ 3) ไว้อย่างน้อย 1 ปี
