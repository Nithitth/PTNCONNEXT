# TCASter Release 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let ม.4–5 students browse every TCAS70 program at 5 universities, see the Round 1 and Round 3 requirements, play with per-exam score sliders, and save up to 5 private targets. Staff see anonymous totals only.

**Architecture:**
- The admin pulls official TCAS JSON into one staging table, one university at a time. They review the differences, then a database function publishes them into live tables.
- Student pages read the live tables with the user's own Supabase client (RLS).
- All scoring logic is pure and unit-tested in `src/lib/tcas.ts`. Turning raw TCAS JSON into rows is pure too, in `src/lib/tcasSource.ts`.

**Tech Stack:** Next.js 16 App Router, Supabase (Postgres, RLS, RPC), Tailwind v4, node:test via tsx. No new dependencies.

**Spec:** `docs/specs/2026-11-11-tcaster-design.md`

## Global Constraints

- **Copy:** all user-facing copy is Thai. Dates use th-TH with พ.ศ.; reuse `formatDateTime` from `src/lib/calendar.ts`.
- **Node 22+.** Never edit source files with Windows PowerShell `Get-Content` / `Set-Content`; use the Edit tool or Node.
- **Migrations:** they're pasted into the Supabase SQL Editor by the user. Never edit an applied one; this release's file is `supabase/migrations/0007_tcaster.sql`.
- **Supabase clients:** use the user's own client by default. The admin client is only for the TCAS pull and the staging reads, and only after `requireProfile({ roles: ["admin"] })`.
- **UI:** use the design system in CLAUDE.md (tokens, `Card`, `Notice`, `buttonStyles`, `smallButtonStyles`, `AdminNav`). Pages must work at 375px with no horizontal scroll.
- **Universities and their TCAS ids:**
  - `001` จุฬาลงกรณ์มหาวิทยาลัย
  - `002` มหาวิทยาลัยเกษตรศาสตร์
  - `005` มหาวิทยาลัยธรรมศาสตร์
  - `006` มหาวิทยาลัยมหิดล
  - `009` มหาวิทยาลัยศรีนครินทรวิโรฒ
- **TCAS year:** `TCAS_YEAR = 2570`. Round types are `"1_2570"` and `"3_2570"`.
- **Source:** `https://my-tcas.s3.ap-southeast-1.amazonaws.com/mytcas/`, with `courses.json` and `rounds/<program_id>.json`.
  - Always add `?ts=<Date.now()>`, because a missing cache-buster can return an XML error.
  - User-Agent: `PTN-Connext/1.0 (school planning tool)`. No personal data in requests.
- **Exact copy:**
  - Source credit on every program page: `ข้อมูล TCAS70 จาก mytcas.com (ทปอ.) · อัปเดต <date>`, linking to `https://course.mytcas.com/programs/<program_id>`.
  - Calculator warning: `เกณฑ์ TCAS70 — ปีที่น้องสมัครอาจเปลี่ยน ใช้เป็นแนวทาง`. Also show `คะแนนขั้นต่ำไม่ใช่คะแนนที่ติดจริง`.
  - Inactive target: `หลักสูตรนี้ไม่มีในข้อมูลล่าสุด`.
  - Unsupported formula: `โครงการนี้ใช้เกณฑ์พิเศษ ดูรายละเอียดที่ mytcas`.
- **Limits:** at most 5 saved targets per student. Staff totals hide groups under 3 students. Teachers are read-only.
- **Privacy:** saved targets and slider scores are visible to their owner only. Admins can't read them either.

## Review Focus

1. **Programs with no Round 3, or an unsupported formula.** Unsupported means `cal_*` keys, university-only exams such as `tu002`, `vnet_*`, weights not summing to 100, or `score_condition` keys. These must show the unsupported message and no sliders, never a wrong total. Owned by Task 1 (`checkRound3`) and Task 7.
2. **TCAS failing partway through a pull.** A failed `courses.json`, or a network error, aborts the pull and leaves the live data and the previous staging untouched. A single program's 403 or XML reply just means that program has no rounds. Owned by Task 3 (`parseRounds`) and Task 4.
3. **Search text with PostgREST-breaking characters** (`,`, `(`, `)`, `%`, `*`, `.`) must not error or change the filter. Owned by Task 1 (`cleanSearch`).
4. **Tampered saves:** an unknown exam code, a score out of range, NaN, a 6th target, or a target for another student must all be rejected. Owned by Task 1 (`cleanScores`), Task 8 and Task 10.
5. **A saved target after a re-publish.** If its program is now inactive, or its Round 3 option index no longer exists, show the inactive notice or fall back to the first option. It must not crash. Owned by Task 1 (`pickOption`) and Task 8.

- [ ] **Step 1: Write the migration.** Make it idempotent (`if not exists` / `create or replace` / `drop policy if exists`), and put a header comment like `0005`'s.

    - The live tables (`tcas_programs`, `tcas_round1_projects`, `tcas_round3`) can be read by `authenticated` when `my_role() is not null`. There are no write policies; only the publish function writes them.
    - `tcas_staging`: RLS is on, with **no policies**. Only the service key uses it.
    - `tcas_publishes`: admins can read it.

  - **`tcas_publish`** is a `security definer` function that raises an exception unless `is_admin()`. Inside the function:
    1. Upsert each staging row's program, setting `active = true`, `published_at = now()` and its fingerprint.
    2. Delete and re-insert the program's round 1 and round 3 rows from the payload.
    3. Count each program as added (it wasn't live before) or changed (its fingerprint differs).
    4. Set `active = false` on that university's live programs that aren't in staging, and count them as removed.
    5. Insert a `tcas_publishes` row with `auth.uid()`.
    6. Delete that university's staging rows.
    7. Return the counts.
    The whole function is one transaction, so any error rolls everything back. The payload's JSON field names are defined in Task 3.
  - **`tcas_target_totals`** is a `security definer` function that raises unless `is_staff()`. It joins targets → programs (active only) → profiles → classrooms, groups by `group_field, faculty, university_name, grade`, and keeps groups with `count(distinct student_id) >= 3`.

- [ ] **Step 1: Implement `tcasFetch.ts`.**
  - Use the base URL, the `?ts=` cache-buster and the User-Agent from Global Constraints.
  - Each request gets a 15 s timeout via `AbortSignal.timeout(15000)`.
